# AutoGuide AI

A local Streamlit assistant for vehicle recall information and safety-feature
explanations. It retrieves official NHTSA recall records and NHTSA publications
from the Federal Register, displays source links, and refuses unsupported
vehicle/VIN/prediction questions.

## Run in PyCharm on Windows

From the project root with the project's `.venv` activated:

```powershell
python -m pip install -r requirements.txt
python ingest.py --features
python -m streamlit run app.py
```

Open the Local URL printed by Streamlit, usually http://localhost:8501.
Leave Streamlit's optional first-run email prompt blank and press Enter.
After updating Python modules, stop Streamlit with Ctrl+C and run it again
to reload imported code. Clear conversation before retesting: old messages
are stored responses and are not regenerated by a page refresh.
The sidebar's **Prepare knowledge base** button performs collection and
chunking as an alternative to `ingest.py`. Existing data remains usable when
some sources cannot be refreshed; consult terminal output for collection errors.

**Source passages** is the default and requires no API key. Feature questions
receive a brief explanation assembled from substantive source sentences;
headings are excluded and sentences can come from different retrieved chunks.
Recall questions show the source summary, safety consequence, and remedy. Choose
**AI summary** to generate a grounded explanation with numbered references.
Enter an OpenAI API key in the password field, or copy `.env.example` to `.env`
and set `OPENAI_API_KEY`. Never commit `.env`. Codex/ChatGPT sign-in does not
set this application's API key. Generation failures are displayed, not replaced
by fabricated answers.

Select a vehicle for recall questions, or use All vehicles and include the
make, model, and year in the question. For general feature questions, select
All vehicles. Chat history lasts for the current browser session. A question
must specify its vehicle; follow-up pronouns do not inherit a previous vehicle.
Use **Add another vehicle** in the sidebar to fetch recall data for another
make/model/year. A zero-result API response does not verify an individual VIN.

Example questions:

- What recalls affect a 2020 Honda Accord?
- What is the fuel pump recall for a 2020 Toyota Camry?
- What is automatic emergency braking?
- How do tire pressure monitoring systems work?

## Semantic search

**Semantic search and reranking** is enabled by default in the sidebar. The first question
downloads all-MiniLM-L6-v2 and the cross-encoder model, then builds ChromaDB.
This can take several minutes. Keyword search remains available when models
cannot be loaded, and the app displays a warning about the fallback.
To prepare the index from the terminal:

```powershell
python ingest.py --skip-fetch --index
python -m rag.retrieval "automatic emergency braking"
```

Pipeline: collection → normalization → chunks → BM25 + MiniLM/Chroma →
reciprocal rank fusion → cross-encoder → up to five evidence chunks →
relevance check → excerpts or optional OpenAI answer → reference validation.

MiniLM embeddings pool short token windows to retain content beyond the
model's normal input limit. Chroma reconciles changed and removed chunks.
Source titles, URLs, publication/retrieval dates, campaign numbers, and vehicle
metadata are retained throughout the pipeline. Paths resolve from the project
root rather than the shell's current directory.

## Chunking experiments

```powershell
python -m rag.chunking --strategy fixed --chunk-size 500 --overlap 100
python -m rag.chunking --strategy structure --chunk-size 500 --overlap 100
```

Both use cl100k token counts. Structure-aware chunking packs recall sections
without splitting short records; oversized sections use overlapping windows.
Switching strategies replaces the active chunk file. Rebuild the index or start
a new app search after changing it. Long Federal Register documents currently
use fixed windows when structured headings are unavailable.

## Tests and evaluation

```powershell
python -m pytest -q
python -m evaluation.run_evaluation
python -m evaluation.run_evaluation --semantic
```

Evaluation reports are written to `data/evaluation/`. The initial development
set contains 12 manually labelled retrieval questions and six refusal questions.
It measures document hit rate, recall, precision, reciprocal rank, refusal
accuracy, and latency. It does not establish answer faithfulness, regulatory
completeness, or final assignment performance. LLM tests use a mock client and
make no paid calls.

## Data scope and remaining assignment work

- The default collector queries five make/model/year combinations. Recall
  counts can change; model-year matches do not establish an open recall for
  an individual VIN. Use https://www.nhtsa.gov/recalls for VIN verification.
- Feature sources are dated NHTSA rule publications, including heavy-vehicle
  stability control. They explain features but cannot establish fitment on an
  individual vehicle or current legal obligations. Source dates are displayed.
- NHTSA's main website returns HTTP 403 in this environment. The collector
  uses available official APIs; it does not bypass the website restriction.
- The professor's 150 permitted webpages, five PDFs, and three table-containing
  pages have **not** been fulfilled by the recall/API corpus. HTML/PDF extractor
  modules exist, but the required corpus and PDF table extraction still need
  validation. The final golden set and human grading of answer faithfulness
  remain assignment work.
- Citation validation checks that referenced evidence numbers exist. It does
  not prove that every generated claim is supported; review source passages.

OpenAI integration uses the existing Chat Completions API:
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
